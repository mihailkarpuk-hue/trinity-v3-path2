## 🔴 ГЛАВНАЯ ОШИБКА (диагноз)

**Идея обогнала программу. Открытия ушли в папку `данные/` и там остались —
в тело программы они не вернулись.**

- Новые оси (FD, взаимовложенность, самоподобие R², модуляция) посчитаны и
  лежат в `данные/фрактальная_карта_буквицы.json`, но:
  - ❌ ядро `ядро/фаза.py` их **не считает**;
  - ❌ приложение их **не показывает**;
  - ❌ экзамен `экзамен/round_trip_score.py` их **не проверяет**.
- Папка данных стала «вторым мозгом», не подключённым к телу. Это прямое
  нарушение твоего правила «единое тело».
- Вдобавок **анализаторов два:** Python `ядро/фаза.py` и JS `приложение/
  общее/атомизация.js` — считают звук по-разному, могут давать разные числа.

Итог: программа цельна **на уровне фазы** (тон/шум/переход — видны), но
**слепа к глубокому незримому** (вложенность, формирование, «жизнь»), ради
которого всё затевалось.

## АУДИТ ПО 5 КРИТЕРИЯМ ЦЕЛОСТНОСТИ ЛИНЗЫ

| Критерий | Оценка | Где разрыв |
|---|---|---|
| Фрактальность (часть = целое) | ⚠️ частично | новые оси не повторены ни в одной части кода |
| Взаимовложенность (части вложены) | ❌ два шва | app↔ядро (два анализатора); данные↔код (оси снаружи) |
| Общая среда (единый носитель) | ⚠️ только фаза | у новых осей нет общей среды с кодом |
| Резонанс (живой отклик) | ⚠️ частично | «дышит» лишь проекция Образ, остальные статичны |
| Эмерджентность (новое качество) | ✅ на старом уровне | образ рождается, но без слоя вложенности/формирования |

## ✅ ЗАДАНИЕ: ВЕРНУТЬ ОСИ В ТЕЛО

Цель — чтобы программа видела то незримое, что мы научились измерять.
Пять шагов, по приоритету:

### 1. Новые оси — в ядро (один анализатор)
**Файл:** `ядро/фаза.py`
Добавить функции рядом с фазой (тот же вход, та же среда):
- `higuchi_fd(x)` → FD (есть готовый код в наших скриптах);
- `selfsim_r2(x)` → линейность лог-лог (истинность фрактала);
- `nestedness(x, sr)` → корреляция огибающих октавных полос;
- `modulation(x, sr)` → глубина модуляции + ведущий ритм.
Выход анализатора расширить: к `{phase, harmonicity}` добавить
`{fd, r2, nestedness, mod_depth, mod_rate}`.

### 2. Один анализатор вместо двух
**Файлы:** `приложение/общее/атомизация.js` ↔ `ядро/фаза.py`
Свести к единому источнику истины: либо JS зовёт результаты ядра (предпросчёт
в JSON-паспорт), либо JS повторяет те же формулы 1:1. Иначе «единого тела» нет.
**Рекомендация:** предпросчитать паспорт каждой клетки ядром → app только читает.

### 3. Экзамен — проверять новые оси
**Файл:** `экзамен/round_trip_score.py`
Добавить round-trip не только фазы, но и FD/вложенности (мы получили r=0.974
для FD — закрепить как авто-тест, а не разовый скрипт).

### 4. Приложение — показывать вложенность/формирование
**Файлы:** `приложение/блоки/просмотр_клеточки/проекция_образ.js`
По законам материализации (см. `КРЕСТЫ_МАППИНГ.md`):
вложенность → иерархия кластеров атомов; FD → зернистость; R² → рекурсия;
модуляция → пульсация во времени. Чтобы незримое стало видно в образе.

### 5. Оживить полный 104-паспорт клетки (убрать 9-агрегатную заглушку)
**Файлы:** `данные/клеточки/каталог.json` (поле `п104`), анализатор
`src/audio-params-104.js` (`analyzeFull104`, реально 103 параметра в 8 группах).
Сейчас `п104` = урезанные **9** агрегатов, из них образ читает **3**.
Задача:
- посчитать **полный 104-паспорт** для каждой клетки → положить как
  `параметры104` (вместо 9-агрегатной заглушки `п104`);
- **атом не трогать** — он остаётся 5-польным (`freq, amp, harmonicity,
  harmonic_index, birth`); 104 — свойства всей КЛЕТКИ, не атома.

**⚠️ ОТКРЫТИЕ (16 июня): «лишние» параметры — это жизнь.**
Анализатор пишет `intrinsic_dimensionality_95pct: 25` → ~25 параметров несут
95% различий МЕЖДУ звуками, остальные ~80 «избыточны» для классификации.
Но проверка показала: именно эти «лишние» (jitter, shimmer, модуляция,
вложенность) несут **различие ЖИВОГО и МАШИННОГО** звука.
Относит. различие живое↔машинное: доминантные спектральные **0.07–0.10**
(машина сохраняет), тонкие/«лишние» **0.53–0.58** (машина теряет).
**Вывод:** «избыточные для классификации» ≠ «ненужные» — их роль нести жизнь.
Поэтому в 104-паспорт берём ВСЕ, а не только значимые для различения.
Схема: `Тринити_лишние_параметры_жизнь.png`.

## КРИТЕРИЙ ГОТОВНОСТИ

проверяет round-trip'ом · приложение их показывает в образе · мёртвых полей
нет. Тогда «незримо видимое» (вложенность, формирование) станет видимым —
и тело догонит идею.
