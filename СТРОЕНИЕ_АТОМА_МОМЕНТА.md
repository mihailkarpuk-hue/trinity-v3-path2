## 0. Мельчайшая единица

```
АТОМ  =  ПРОТОН  +  ЭЛЕКТРОН  +  ЧАСТИЧКА ЖИВОГО ОБРАЗА
         (числа)    (числа)       (видимое, синхронно со звуком)
```

Без любого из трёх слотов атом **неполон**.  
Дальше сборка только из целых атомов: **клетка → орган → организм**.

Ориентир по числам (канон KEYS_108):
- **протон — 61** ключ: SPECTRAL + VOCAL + MUSICAL + PERCEPTUAL + mfcc_0..12 + zcr  
  плюс носитель звука: спектр mag+phase в `.npz`
- **электрон — 47** ключей: TEMPORAL + SPATIAL + MOVEMENT + mfcc_delta_* + AXES  
  (при моно SPATIAL = статус `н/п_моно`, не ложные нули «для галочки»)
- **вместе 108** + **образ_кусочек** (слот вне счёта ключей, но обязателен)

## 1. Три слота внутри атома (обязательны)

```
        ┌──────────────── АТОМ-МОМЕНТ (один t, ~46 мс) ────────────────┐
        │                                                              │
        │  ● ПРОТОН — «тяжёлая» половина параметров + спектр звука     │
        │       mag[513] + phase[513]  →  обратимый звук (.npz)        │
        │       + группа параметров-протона (~56)                      │
        │                                                              │
        │  ○ ЭЛЕКТРОН — «лёгкая» половина параметров                   │
        │       группа параметров-электрона (~47)                      │
        │       протон + электрон ≈ полнота 108 на атоме               │
        │                                                              │
        │  ◆ ЧАСТИЧКА ЖИВОГО ОБРАЗА — кусочек сцены в ТОТ ЖЕ момент   │
        │       синхронно со звуком (тот же t / тот же старт)          │
        │       не вычислять «вместо жизни» из freqToHue               │
        │       хранить: точки/пиксели/штрих живого образа + цвет      │
        │       из палитры живой клетки / органа                       │
        │                                                              │
        │  метки: t, старт  ·  кресты к соседям (связи, не замена      │
        │         слотов выше)                                         │
        └──────────────────────────────────────────────────────────────┘
                              │
                              ▼
                    КЛЕТКА → ОРГАН → ОРГАНИЗМ
```

### Зачем слот образа отдельно от параметров

Параметры описывают момент числами.  
**Частичка образа** — это физический видимый кусок мира в тот же миг: то, что глаз видит, пока ухо слышит этот атом.

| Слот | Вопрос | Не путать с |
|------|--------|-------------|
| Протон | Как звучит / чем «массивен» момент | картинкой |
| Электрон | Как измеряется в остальных осях | геометрией сцены |
| **Частичка образа** | **Как выглядит** в тот же `t` | одним центроидом или hue из частоты |

Правило синхрона: **один `t` (или `старт`) на звук и на кусочек образа.** Сдвиг образа относительно звука внутри атома запрещён.

## 2. Что писать в «частичку живого образа»

Минимум (архитектурный контракт):

```text
образ_кусочек: {
  t | старт     — тот же, что у звука атома
  точки[]       — фрагмент живого образа:
                  { x, y, размер?, r, g, b }  и/или пики, развёрнутые по частоте
  источник      — откуда кусок (живая клетка V3, кадр сцены, …)
  палитра_ссылка — цвет из живого образа, НЕ freqToHue(звук)
}
```

Уже близко в коде/каноне: `пики`, `форма`, `палитра_образа` органа — но слот должен быть **явным полем атома**, а не побочным эффектом синтеза.

Нельзя:
- одна точка на весь атом «для галочки»;
- цвет только из частоты звука;
- образ «потом нарисуем из спектра» без записи живого куска в архив.

## 3. npz и манифест

| Где | Что |
|-----|-----|
| **`.npz`** | Спектр протона: `mag`, `phase` (живой звук) |
| **манифест / атом** | Протон-параметры, электрон-параметры, **`образ_кусочек`**, t, кресты |
| **орган** | палитра живого образа (общая для окраски), оси потока, клетки |

---

## 4. «Дописать архив» в этой схеме

Не «сдать половину 108 на орган», а:

1. **Внутри атома** — разметить протон / электрон / **слот образа**; дописать недостающее, чтобы атом был полным.  
2. **Выше** — клетка / орган / организм собирают уже **целые** атомы (плюс свои поля потока, если нужны).

---

## 6. Приёмка архитектуры атома

Атом в архиве считается полным, если есть:

- [ ] спектр (протон-носитель звука)  
- [ ] параметры протона + электрона (нарезка групп зафиксирована)  
- [ ] **`образ_кусочек` с тем же t, что звук**  
- [ ] цвет/точки из живого образа, не freqToHue  

Без пункта образа — атом не принимать в «полный» архив.
