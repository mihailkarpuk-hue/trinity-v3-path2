# ТРИНИТИ V3 «Атомы Звука» — максимальный анализ крайнего варианта

> Самодостаточный разбор для передачи в отдельный Claude chat (в т.ч. для «Fabel 5»).
> Дата среза: 2026-07-05. Собрано прямой разведкой по коду и данным, не по памяти.
> Где утверждение опирается на внутренние доки, а не на независимую проверку — помечено «(заявлено)».

---

## 0. TL;DR — что это и где сейчас находится

**Тринити V3** — детерминированный переводчик «звук → физически узнаваемый образ». Не классификатор и не ML-чёрный ящик: каждый визуальный признак есть функция измеренной физической величины. Один звук → одна форма → всегда воспроизводимо (заявлено как ключевое отличие от генеративного ИИ).

Ядро идеи — **атом звука**. Звук раскладывается на атомы (зёрна во времени/частоте), и каждый атом несёт «частицу целого» — полный паспорт из **104 параметров + 5 осей = 108 измерений**. Дальше атомы (а) собираются в **образ** (облако точек) и/или **сцену** (эталонная 3D-модель явления) и (б) **узнаются** — сопоставляются с банком живых чистых образов.

**Состояние крайнего варианта:**
- Пайплайн слух → паспорт → узнавание → образ собран и работает в браузере (порт 8014).
- Только что (эта сессия): узнавание переведено с 5 признаков на полные **108** с корректным откатом на 5.
- Обогащены полным per-atom паспортом **55 файлов** (18 базис-эталонов + 37 живых букв) — на них узнавание идёт в «режиме 108».
- Остальные 95 клеток каталога несут только агрегатный паспорт (per-atom нет) → на них работает откат.

**Главное открытое напряжение:** узнавание в 108-мерном z-пространстве сейчас тянет «каплю» к гласным буквицам (П/О/К). Это сигнал, что евклид по 108 сырым осям + агрегирование средним по атомам — слишком грубая метрика. См. §7 и §9.

## 2. Концепция «слуха» (манифест, сквозная для V3)

Четыре уровня понимания звука (заявлено):
1. **Частоты** — умеет любой FFT.
2. **Паттерн** — умеет ML-классификатор («вероятно, виолончель»).
3. **Физика** — здесь начинается Тринити: «220 Гц с таким затуханием = металлическая струна, смычок, резонирующее тело» — детерминированная геометрия.
4. **Присутствие** — горизонт: голос несёт физиологию (размер тракта), состояние (тремор), намерение. Чтение пространственной формы.

Тезис: «Это не обработка. Это восприятие». Детерминизм (один звук → одна форма → навсегда) заявлен как то, что нельзя скопировать генеративным ИИ, и как основа объяснимости/доверия.

## 4. Анатомия атома — три уровня глубины

Это концептуальное ядро всей системы.

### Уровень 1 — ЯДРО (7 полей, неизменный скелет)
`ядро/паспорт_атома.py::ядро()`:
```
birth          — время рождения (сек)
freq           — основная частота (Гц)
amp            — амплитуда [0,1]
phase          — фаза-состояние: тон / шум / переход
harmonicity    — гармоничность [0,1]
harmonic_index — номер гармоники (1..n)
lifetime       — длительность (сек)
```

### Уровень 2 — ЛОКАЛЬНЫЕ ПРИЗНАКИ + рендер (то, что реально лежит в атоме)
В файлах атомов на атом дополнительно: `pos_x/y/z`, `color_r/g/b`, `size`, `spectral_width`, `centroid_local`, `brightness_local`, `noisiness_local`, `dissonance_local`, `freq_modulation`, `amp_modulation`, `timbre_modulation`, `relative_time`, `relative_loudness`, `envelope_phase`, ссылки на родителя (`parent_*`).

### Уровень 3 — ПОЛНЫЙ ПАСПОРТ `params_104` (108 измерений)
Опционально на атом (у 55 файлов) + всегда как агрегат клетки (`параметры104` / `parent_params_full`).

**Фаза-канон** (`ядро/фаза.py`): `тон` если harmonicity > 0.6; `шум` если < 0.05; иначе `переход`.

## 5. Полный паспорт: 104 параметра + 5 осей = 108

**8 перцептивных групп (103) + ADVANCED (MFCC) + 5 фрактальных осей.**

| Группа | N | Поля (ключевые) |
|---|---|---|
| TEMPORAL | 16 | amplitude_rms/peak/avg, loudness_lufs, crest_factor, dynamic_range, attack/decay/sustain/release, onset_density/strength, bpm, rhythm_stability, bpm_isolation, bpm_periodicity |
| SPECTRAL | 18 | spectral_centroid/spread/skewness/kurtosis/flatness/rolloff_85/flux/slope, low/low_mid/mid/high_mid/high_freq_ratio, pitch_fundamental, harmonic_ratio, inharmonicity, noise_floor, tonality |
| VOCAL | 8 | formant_f1/f2/f3, voicing_ratio, breathiness, roughness, jitter, shimmer |
| MUSICAL | 14 | 12× chroma (C…B), key_dominant, consonance |
| SPATIAL | 5 | stereo_width, stereo_correlation, spatial_impression, reverb_estimate, direct_to_reverb_ratio |
| PERCEPTUAL | 7 | perceptual_sharpness/softness/tension/plushness/warmth/brightness/density |
| MOVEMENT | 8 | movement_explosion/resonance/flow/mist/fracture, self_similarity_index, amplitude_modulation_smoothness, ring_decay |
| ADVANCED | 27 | mfcc_0..12, mfcc_delta_0..12, zero_crossing_rate |
| **5 ОСЕЙ** | 5 | fd, selfsim_r2, nestedness, mod_depth, mod_rate |

**Сумма:** 16+18+8+14+5+7+8+27 = 103; +5 осей = **108**. ✔

### Пять осей (ядро/оси.py) — «фрактальная линза»
- **fd** — фрактальная размерность Хигучи. Калибровка (заявлено): гласная У ≈ 0.09, шум С ≈ 1.06. Мера «шершавости»/многомасштабности волны.
- **selfsim_r2** — R² лог-лог фита, насколько звук истинно фрактален.
- **nestedness** — временная связанность октавных полос (средняя кросс-корреляция огибающих Гильберта). Гласные ≈ 0.9, плоский шум ≈ 0. Антикорреляция с fd ≈ −0.57 (заявлено).
- **mod_depth** — глубина амплитудной модуляции (std/mean огибающей).
- **mod_rate** — ведущая частота модуляции (Гц) из Welch, полоса 0.5–40 Гц.

### ⚠️ Расхождение имён ключей (важно для узнавания)
Канон в `паспорт_атома.py` использует `chroma_Csharp`; **реальные данные** используют `chroma_Cs` и содержат `mfcc_*`/`mfcc_delta_*`. Поэтому набор из 108 ключей выведен эмпирически как **пересечение числовых ключей по всем 150 клеткам** (сохранён в `/tmp/keys108.json`). Это стоит зафиксировать канонически, иначе любой будущий строитель индекса разъедется с данными.

## 6. Как рождаются атомы (атомизация)

`scripts/пересборка_живых_букв.py::атомизировать()` (SR=22050, N=2048, HOP=512 ≈ 16 мс, окно Ханна):

Для каждого кадра считается **flatness** = геом.среднее / ариф.среднее спектра.
- **flat > 0.4 → ШУМ:** энергия по 19 лог-полосам [60…9000 Гц]; атом на полосу с частотой = геом.центр полосы, amp = min(1, e·6), harmonicity = 0.
- **иначе → ТОН:** локальные пики спектра; harmonicity = 1.0 если flat<0.15 иначе 0.4.

Гармоничность отдельно уточняется через **HPS** (`ядро/фаза.py::hps_harm`): произведение децимированных гармоник 2/3/4, оценка pitch, доля энергии в гармониках (эвристический масштаб ×6).

Затем атомы «насаживаются» на 3D-архетип формы (1500 точек): birth нормируется вдоль формы, назначаются `pos_*`, `color_*` из hue/sat, фаза из кадров огибающей.

### Обогащение до 108 (`обогатить_атомы_104.py`)
`WINDOW_MS=200` (±100 мс), `SR_ATOM=16000`. Для каждого атома: окно вокруг `birth` → `analyze_full_103(chunk)` + `оси_звука(chunk)` → `atom.params_104` (108). Агрегат клетки = среднее по атомам. Кресты пересобираются (`кресты.py::собрать_клетку`).

## 7. Узнавание — крайнее состояние (эта сессия)

`приложение/общее/узнавание.js`:
- **Основной путь (108):** `вектор108()` = среднее `params_104` по атомам с полным паспортом; z-нормировка по `mu/sd`; расстояние = евклид, нормированный на √108, по индексу `данные/узнавание_индекс_108.json` (150 клеток × 108 осей). top-k.
- **Откат (5 фич):** старый путь `фичи()` = [тон, шум, переход, log_centroid, harm] по `узнавание_индекс.json`, когда у атомов нет `params_104`.
- Плашка сообщает, каким путём прошло узнавание.

Строитель индекса: `построить_индекс_108.py` (mu/sd, защита от константных осей sd<1e-9→1).

**Проверено в браузере:**
- капля (12/12 атомов с паспортом), пила (6100/6100) → режим 108.
- клетка дождя без per-atom паспорта → чистый откат на 5-dim, без ошибок.

**Проблема качества:** капля в 108-режиме тянется к живым гласным П/О/К (d≈1.18). Это не физически осмысленное соседство. Причины-кандидаты в §9.

## 9. Критический разбор и открытые вопросы (для совместного думанья)

### A. Узнавание — метрика слишком грубая
1. **Сырой евклид по 108 осям.** Оси разной природы (Гц, дБ, безразмерные, MFCC-кепстры) и разной надёжности. z-норма уравнивает дисперсию, но не значимость. → капля ≈ гласные.
   - Идеи: обучаемые/экспертные веса групп; отбор дискриминативных осей (PCA/LDA/mutual info); блочные расстояния по группам с последующей агрегацией; косинус вместо евклида.
2. **Агрегирование средним по атомам стирает структуру.** Звук — это распределение атомов во времени/частоте, а не одна средняя точка. Капля (12 атомов) и гласная (сотни) сводятся к одной точке. → теряется именно то, что делает каплю каплей.
   - Идеи: сравнение распределений (EMD/Wasserstein, MMD); гистограммы по фазе/полосам; несколько центроидов (кластеры атомов); учитывать `кресты` (топологию связей), а не только облако.
3. **База для сопоставления смешанная.** В индексе 150 клеток всех групп; «живые чистые образы» (18 базис + 37 букв) не выделены как приоритетный пул. Автор явно хотел сопоставлять с чистыми образами.
   - Идея: двухступенчато — сначала матч по приоритетному пулу чистых образов, потом уточнение.

### B. Паспорт и данные
4. **Разъезд имён ключей** (chroma_Cs vs chroma_Csharp; mfcc_* вне канона). Нужен единый канон ключей, иначе индексы и анализатор дрейфуют.
5. **Per-atom паспорт только у 55/150.** Пока «режим 108» доступен не для всех клеток. Нужно решить: обогащать остальные или оставить откат осознанным.
6. **Окно ±100 мс на атом** для коротких атомов (капля: 12 атомов) может захватывать соседние события → «размазывание» паспорта.

### C. Образ и сцена
7. **Образ = среднее+облако**, сцена = преднастроенная модель по типу. Между «измеренным паспортом» и «формой» пока нет полного обратимого моста для произвольного звука (round-trip заявлен r≈0.974 по оси fd на 37 буквах, но это ось, не форма).
8. **Наследие визуальных багов** предыдущей линии (мерцание HEARTBEAT, застывание pink при тишине, WAVES «не как волна») — проверить, не перекочевали ли паттерны в сцены V3.

### D. Что измерить, чтобы двигаться
- Матрица узнавания: для каждого из 55 обогащённых образов — top-5 соседей. Ожидание: капля→капле-подобные, буква→буквам. Сейчас явно не так → это первый эксперимент.
- Абляция: какой вклад в различение дают группы (только оси? только MFCC? только SPECTRAL?).
